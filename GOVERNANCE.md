# Governance

lambda128 is a **single-maintainer project** with a path toward community governance.

## Current Structure

The Project Maintainer (Androvon X) holds final decision-making authority over:
- Code acceptance and rejection
- Release management
- Licensing and commercial terms
- Project direction
- Maintainer appointment and removal

## Maintainers

Maintainers are trusted contributors with commit access. See [MAINTAINERS.md](./MAINTAINERS.md) for the current list.

Maintainer privileges:
- Merge approved pull requests
- Triage issues
- Manage releases
- Participate in architectural decisions

Maintainers **do not** have authority over:
- Licensing decisions
- Commercial agreements
- Trademark usage
- Transfer of project ownership

## Decision Making

1. **RFC Process**: Major architectural changes should be proposed via GitHub Discussions before implementation
2. **PR Review**: All pull requests require at least one maintainer review
3. **Consensus**: Maintainers aim for consensus; the Project Maintainer breaks ties
4. **Veto**: The Project Maintainer reserves a veto on any decision

## Future Community Governance

As the project matures and the contributor base grows, we plan to establish:
- A technical steering committee
- Formal RFC process
- Community voting for major decisions
- Transfer of some authority from the Project Maintainer to the committee

## Code of Conduct

All participants must follow the [Code of Conduct](./CODE_OF_CONDUCT.md).
